# Flare20 full equilibrium on 211 nodes

The literal Flare20 PM2 model reaches full load on **211 nodes and 2,740
unknowns**, with **17 accepted load steps, zero rejected load attempts** and
a freshly rebuilt final residual of **2.0584e-13**. The numerical solution is
converged, but the mesh is **not yet resolved at the required 0.1%**: the
107/211-node pair passes **0/7** root-moment and per-beam nodal-field checks.
These are numerical mesh checks, separate from the 5% ASWING allowance.
FFWT-4 native coverage remains **200/8,000**.

## Execution and independent audit

All jobs run serially with one BLAS thread, a 512 MiB address-space limit
and a 90-second process cap. Of 14 solver processes, **13 exit successfully
and one exits 124**. The timed-out two-step job had already written a full
result and its completed helper report. Its exit code remains unchanged.
Before resuming, a separate audit rebuilt its saved boundary and every
predecessor, checked physical residuals, source/kernel hashes, exact requests,
checkpoint joins and the five-degree Newton guard. Only that verified saved
boundary was reused; a timeout alone is never authority to continue.

Subsequent jobs accept at most one load step. All nine exit successfully in
**47.84–66.15 seconds** each. Across the whole chain, the largest freshly
rebuilt boundary residual is **8.7110e-13**, below 1e-12. The sum of recorded
dispatch/rebuild intervals is 653.31 seconds; this excludes Python startup
and gaps between jobs and is not an end-to-end browser timing.

The original strict assessor and its earlier reports remain unchanged.
`assess-isae-ffwt4-continuation-v2.py` requires explicit timeout opt-in,
complete hash-bound output, and all normal independent physical checks.
It reports process failures separately from numerical load-step rejection.
Twelve audit regression tests and nine nodal-field comparison tests pass.
All 139 production kernel modules remain identical to the already tested
rank-refined archive; no physical equation or tolerance changes here.
